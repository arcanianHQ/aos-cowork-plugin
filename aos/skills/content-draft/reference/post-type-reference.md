# Post type — Reference (project-tied case study)

> **What it is.** A real customer project, photographed and written up. Highest-converting content type for physical-product brands because it provides social proof + product-in-context + credibility in one piece.
>
> **Premium-pole variant note (Deluxe-specific, 2026-05-14, S2 pivot):** For brands targeting an architectural-magazine audience (Szép Házak / Octogon-style), the Reference post adopts a magazine-editorial register — third-person, anonymous role-naming, aesthetic justification over technical imperative. See "Premium-pole variant" section below.

## Goal

Build social trust. Convince a prospect that *people like them* hire this brand and get results they want. Secondary: SEO via long-tail product+location queries.

## Structure (default — 800–1500 words; previously 300–600 was too short for Premium-pole architectural-magazine target)

1. **Hook (1–2 sentences)** — name the *starting situation* concretely, in the magazine-editorial register. NOT meta-pitch ("In this article we present..."). Direct: *"A family house with a white facade, an established garden, and two cars that needed covered parking — without the garden gaining a new foreign element."*
2. **The project (2–4 sentences)** — anonymous role-naming ("the homeowner", "the tenant", "the family" — NOT "our customer"/"our client"). One concrete location anchor if available (town, region). What they needed, what the constraint was.
3. **The build (3–5 paragraphs)** — what was actually done. Material choices and structural decisions, but **with aesthetic justification, not just technical imperative**. NOT: "this is critical for longevity". YES: "the cup raises the line slightly above the garden level — a softer transition, and the wood doesn't touch the concrete's moisture." Cite specific brand products from `content-system/products.md` only when they add authority or specificity, not as SEO reflex.
4. **The result (2–4 sentences)** — what the property now has. Maximum one direct quote if available and verified. If no real quote, omit entirely — never fabricate.
5. **Image markers** — `[BEFORE]`, `[BUILD-IN-PROGRESS]`, `[AFTER-WIDE]`, `[AFTER-DETAIL]`. The blog version has placeholder lines for the photo team.
6. **Soft advisory CTA (1–2 sentences)** — magazine-style closing, not sales-deck. *"Hasonló helyzetben — meglévő ház, kialakult kert, új igény — szívesen átnézzük együtt, hogyan illeszkedhet hozzá egy új szerkezet. A felmérés helyszíni."* NEVER discount, urgency, or "kosárba" language.

## Premium-pole variant — Szép Lak / Octogon register

When the post is for an architectural-magazine target (Deluxe Building Premium pole, deluxebuilding.hu), apply these additional rules **on top of** the default structure:

- **Third-person register, anonymous role-naming.** *"A tulajdonos"*, *"a lakó"*, *"a megrendelő"* — NEVER *"ügyfelünk"* or *"megrendelőnk"*.
- **No meta-pitch openings.** Do NOT start with *"Ebben a cikkben…"* or *"A következő projektben bemutatjuk…"*. Start in-medias-res with the situation.
- **Aesthetic justification primary, technical secondary.** Material choices motivated by composition/form first; technical advantage mentioned as quiet secondary. Reverse of the Standard-pole register (where technical-spec leads).
- **The building/structure is the subject.** *"A kocsibeálló a ház vonalát folytatja"* — the structure acts. NOT: *"We built the carport so that it would follow the house's line"* — agency-as-subject is sales-deck register.
- **No bullet lists unless genuinely warranted** (rule J2). A magazine post is prose-driven. A bullet list reads as listicle, breaks the register.
- **No FAQ section** unless the post crosses 1500 words (rule J3). A magazine project-reference is rarely long enough to warrant FAQ.
- **Bold-emphasis sparingly** (rule J9). 2–4 bolds per post, only on truly emphasized terms (a specific dimension, a brand-defining material). Not on SEO keywords.
- **Brand-name mentions only when relevant** (rule J6). *"Remmers fedőfesték"* — yes, because the brand carries finish-quality signal. *"Hörmann garázskapu"* — only if the project actually used one. Not as SEO reflex.
- **Social proof (500+ projektek) only if topic-relevant** (rule J5). A standalone project-reference doesn't need the "500+ projects" line — the project itself IS the proof.
- **Cross-pole link rule (J4):** Premium-pole post may NOT link to kocsibeallo.hu (Standard pole, down-funnel). Standard-pole posts MAY link up to deluxebuilding.hu (up-funnel) — but not the reverse.
- **Length target: 800–1500 words** (rule J7) — neither the brief 300–600 of pure social-proof reference, nor the 1500–3000 SEO-listicle.

## Listicle variant (collection — N projects in one post)

When a post collects multiple projects under a theme (the existing Deluxe-blog convention — "Három egyedi kocsibeálló fából", "Three custom carports", etc.), use a separate template. See `post-type-listicle.md` (planned, not yet written) for that variant.

For now: per S1 decision, Reference and Listicle are **two equal-standing types**, choice driven by post goal — Reference for deep single-project narrative; Listicle for SEO-led collection.

## FB caption (~150 chars)

One sentence that creates curiosity, not summary. Photo carries the message; copy makes them click "More" or visit the link.

**Anti-pattern:** ❌ "Új kocsibeálló projektünk Veszprémben — 6×7m, prémium fenyő, 2 hét alatt elkészült. Nézd meg!"
**Better:** ✅ "Mátyásék azt mondták, két télig elviselik még. Egy hét alatt megvolt."

## IG caption (200–400 word sweet spot)

Story-driven. Use the structure of the blog version but in tighter, more personal voice. End with hashtag block.

**Hashtag policy:**
- 8–15 hashtags total
- Mix: brand-specific (#deluxebuilding), category (#kocsibeallo), regional (#magyarorszag, #veszprem), product-specific (#fenyokocsibeallo)
- Avoid generic high-volume tags (#instagood, #love) — pull non-ICP follows that dilute the audience signal

## Pinterest pins (3–5 per reference post)

Pinterest is **search**, not social. Treat each pin like a mini landing page.

### Pin spec template (one per pin)

```
PIN <n>
─────────────────────────
Image direction: <prompt for image team — e.g., "Vertical 2:3, wide afternoon-light shot of the finished structure with one human element (a hand on the post, a parked car), wood grain visible">
Pin title (≤100 chars, keyword-rich): <e.g., "Prémium fenyő kocsibeálló — Veszprém, 6×7m">
Pin description (≤500 chars): <2–3 sentences, search-keyword dense but readable, end with one CTA-shaped line like "Bővebben a hasonló projektekről...">
Destination URL: <blog post URL>
Board hint: <which board this belongs on — "Kocsibeállók", "Garage projects", "Inspiráció">
```

**Vary the 3–5 pins by angle:**
- Pin 1 — finished hero shot (the trophy image)
- Pin 2 — before/after split (highest-saving rate type)
- Pin 3 — detail shot (material quality, joinery, finish)
- Pin 4 — wide context shot (the product in its environment)
- Pin 5 — overhead/aerial OR build-in-progress (varies the visual register)

## Voice notes for reference posts

- **Register (default):** premium-confident, magazine-editorial third person. The role-holder ("the homeowner", "the tenant") is the only place register drops to peer-quote.
- **Numbers:** concrete numbers — meters, weeks, materials, brand names where relevant. Premium positioning is built on specificity, not adjective-stacking.
- **Avoid:** superlatives without proof ("the best", "unique"), discount language, urgency language ("only this month"), AI-marketing buzzwords ("critical", "innovative", "sustainable" as a sole descriptor), meta-pitch openings ("In this article…").
- **Customer quotes:** verbatim, only if verified and approved by the customer. If unverified — omit. Never fabricate even an illustrative customer quote.
- **Anonymous role-naming** (Premium-pole variant): *"a tulajdonos"*, *"a lakó"*, *"a megrendelő"*. NEVER *"ügyfelünk"*, *"megrendelőnk"*. Maintains magazine-editorial frame.

## When NOT to write a reference post

- Project incomplete (no after-photos yet)
- Customer hasn't approved use of their name / property
- Project had quality issues — reference posts must be unambiguous wins, otherwise they damage rather than build trust
- Photos are low-quality — postpone, reshoot

## Frequency

For most physical-product brands: 1–2 reference posts per month. More than that dilutes the "this is a real project we care about" signal — it starts to feel templated.
